# 06 · v1 路线：从"静态快照"升级为"内嵌 gacha-calendar-core"

> 本文是 v1 的**设计约束与接缝说明**，不是待办清单的全部。v0 已经落地，v1 在此基础上增量升级，
> UI 与视图模型不需要重写。

## 1. 为什么要 v1

v0 的数据源是 `gacha-calendar-app` 的 CI 每 6 小时产出的公开快照（`latest.json`）：

- 优点：零 JS 引擎、包体小、不碰第三方源站、不会触发 CORS/反爬；
- 代价：**最多滞后 6 小时**、依赖作者的 CI、无法"来源切换 / 自定义条目 / 逐源自检"。

v1 改成在 widget 进程内嵌 [`gacha-calendar-core`](https://www.npmjs.com/package/gacha-calendar-core)
（零依赖、零宿主依赖的 ESM，`createEngine({ transport, storage, now })`），由每台机器自己抓 28 个源，
恢复 `dsh-gacha-calendar` 的原始设计（无服务端、数据实时）。

## 2. 已经预留的接缝（v0.1.14 起）

```csharp
// src/GachaCalendar.Core/Services/IFeedProvider.cs
public interface IFeedProvider : IDisposable
{
    string CacheDirectory { get; }
    bool TryLoadCached(out FeedDocument? document, out string? error);
    Task<FeedResult> FetchAsync(string url, CancellationToken cancellationToken = default);
}
```

- v0 实现：`FeedClient`（HTTP + ETag + 原子缓存 + 示例兜底）。
- v1 实现：新增 `EngineFeedProvider`，内部跑 core，`FetchAsync` 把 core 的 Result JSON 包成
  `FeedResult(Fresh)`；其余代码（`WidgetViewModel`、预览、面板、设置页）**一行不改**。
- 插件里只有一处依赖具体类型：

```csharp
// GachaWidgetPlugin.cs
private IFeedProvider? _feedClient;   // v0: new FeedClient(...)；v1: new EngineFeedProvider(...)
```

数据形状不变：仍是 `schemaVersion: 1` 的 Result JSON（见 `docs/02-数据契约.md §1`），
`parserVersions` 继续透传用于诊断。

## 3. JS 引擎选型（当前结论：WebView2 优先）

| 方案 | 包体 | ES module | Intl/时区 | 备注 |
|---|---|---|---|---|
| **隐藏 WebView2** | ≈0（Win11 系统自带 Evergreen Runtime） | ✅ | ✅ | WidBar 本身用 WebView2；同一机器保证存在；异步桥需要 postMessage |
| ClearScript V8 | +25~35MB | ✅ | ✅（V8 带 ICU） | 同步调用方便，但要为 x64/arm64 各带一份 native |
| Node sidecar | +50~70MB | ✅ | ✅ | 可直接复用 `packages/engine/host.mjs` 的 JSON-lines 协议，但包体不可接受 |
| Jint | +1MB | 部分 | ❌ 无 Intl | **不可用**：core 用 `Intl.DateTimeFormat` 算时区，缺失会静默偏 8–9 小时 |

**推荐 WebView2**：
- 只在需要刷新时创建/加载 `core.mjs`（隐藏窗口），完成后保留实例；
- 用 `WebMessage` 桥把 `transport.fetchRaw` / `transport.fetchViaProxy` 转到 C#（`HttpClient` 无 CORS、可设任意 header，
  所以两个方法可以共用一个实现）；
- `storage` 用插件自己的 JSON（WidBar 的 `SettingsJson` + 一个 `engine-cache.json`），键名沿用 core 的
  `hidden/shown/removed/order/customUrls/customEntries`；
- `now` 直接传 `DateTimeOffset.UtcNow`。

若目标机器缺 WebView2 Runtime：降级为 v0 的 `FeedClient`（保留两条实现，运行时探测），
并在设置页"数据检查"里显示原因。

## 4. 分阶段任务

| 阶段 | 内容 | 验收 |
|---|---|---|
| v1-a | `EngineFeedProvider` + 隐藏 WebView2 加载 core，`FetchAsync` 跑通 28 款 | 面板 28 款、状态"联网数据"、`widget.log` 里 core 耗时 < 8s |
| v1-b | 刷新节流 + 567 退避重试（bwiki 风控） | 连续刷新不触发 567；失败自动沿用缓存并标 stale |
| v1-c | 设置页加"解析器自检"（core 的 `selfCheck()`） | 逐源输出 正常/未公布/报错，只读不改缓存 |
| v1-d | 来源切换 + 自定义条目表单 | 与 DSH 插件设置项对齐（订阅 `customUrls`/`customEntries`） |
| v1-e | 包体与启动时间回归 | msix ≤ 45MB；冷启动首帧仍来自缓存（< 300ms） |

## 5. 不做的事

- 不把 core 的解析器复制进 C#（解析器只在 core 里改，升级 npm 依赖即可）；
- 不在预览里跑 WebView2（任务栏 48px 的预览只读已算好的 JSON）；
- 不引入服务端中转。
