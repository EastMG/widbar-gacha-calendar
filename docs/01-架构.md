# 01 · 架构

## 1. 形态变化：从"自己占任务栏"到"WidBar 的插件"

WPF 版（`gacha-calendar`）自己实现任务栏集成：定位 `Shell_TrayWnd`、置顶停靠窗、不进 Alt+Tab、
托盘、单实例、自启、多显示器。代价是这些全部要自己维护，且与系统"小组件"按钮抢位置。

WidBar 把这一层做成了宿主能力：

| 能力 | WPF 版 | WidBar 版 |
|---|---|---|
| 任务栏位置/空闲区检测 | 自己算 `Shell_TrayWnd` 几何 | **WidBar 提供**（拖到绿色空位即可） |
| 悬停/点击打开浮出层 | 自己写 | **WidBar 提供** |
| 深浅色主题 | 自己跟随 | **WidBar 注入**，用 `ThemeResource` 自动跟随 |
| 浮出层材质（Mica/Acrylic） | 自己选 | **用户选**，所有 widget 统一 |
| 托盘/自启/单实例 | 自己写 | 不需要（WidBar 常驻托盘） |
| 崩溃恢复 | 无 | **宿主重启 widget 进程**（指数退避，连崩 3 次禁用） |
| 多实例 | 单实例 | 同一个 widget 可放多份，每份独立设置 |

结论：本仓库**只写三块 UI + 一份数据层**，任务栏相关的 Win32 代码全部删掉。

## 2. 分层

```
┌─ src/GachaWidget/（WinUI 3，WidBar 插件）
│    Plugin/GachaWidgetPlugin.cs   实现 WidgetPluginBase / IConfigurableWidgetPlugin
│    Views/PreviewView.xaml         任务栏预览条（宽 180–360 逻辑像素，高随任务栏）
│    Views/FlyoutView.xaml          展开面板（28 款六列表格）
│    Views/SettingsView.xaml        设置页（宿主提供保存/取消 + 实时预览）
│    Services/IconCache.cs          图标下载 + 落盘缓存（失败退回首字色块）
│    Services/RefreshScheduler.cs   按 due 刷新（分钟级 Tick + 手动刷新）
├─ src/GachaCalendar.Core/（net8.0，无 UI 依赖）
│    Models/                         feed / catalog / settings
│    Services/FeedClient.cs          HTTP + ETag + 原子缓存 + 示例兜底
│    Services/CatalogStore.cs        28 款元信息（EmbeddedResource）
│    ViewModels/RowBuilder.cs        Result JSON → 行文案（与 WPF 版逐条一致）
│    ViewModels/WidgetViewModel.cs   可见行 / 预览条 chips / 状态文案
└─ data/                            catalog.json、sample-feed.json
```

**Core 不引任何 WinUI/WPF 类型**，所以它可以被单测直接跑，也能被将来别的壳复用。

## 3. 数据流

```
WidBar 启动 widget 进程
  → Plugin.InitializeAsync(context)
      读 context.SettingsJson → WidgetSettings
      读 DataDirectory 下的缓存 feed（立刻有内容，不等网络）
      创建 PreviewView（先渲染缓存）
  → RefreshScheduler：到 due 就 RefreshAsync()
      FeedClient.FetchAsync(feedUrl)  ──HTTP──▶ GitHub Pages latest.json
         ├─ 200 → 解析 → 原子写缓存 → WidgetViewModel.Apply
         ├─ 304 → 用缓存
         └─ 失败 → 用缓存；无缓存 → 用内置 sample feed（状态标「示例数据」）
  → PreviewView/FlyoutView 绑定 WidgetViewModel，每分钟 Tick 一次刷新倒计时
```

**为什么 UI 线程不直接做 HTTP**：WidBar 的 preview 是真实 WinUI 元素，卡住 UI 会让任务栏这一小块
掉帧。所有网络在后台线程，结果回 UI 线程（`DispatcherQueue.TryEnqueue`）。

## 4. 生命周期与开销

- preview 只画 1–3 个 chip，**不做动画、不轮播**（轮播交给 WidBar 的 Smart Stack）。
- 进了 Smart Stack 后台（`IWidgetContext.IsPreviewVisible == false`）时暂停图标下载与 tick 以外的所有工作。
- flyout 内容只创建一次、复用；关掉时通过 `IWidgetFlyoutLifecycle.OnFlyoutHidden` 停掉滚动/动画。
- 网络：首次启动一次，之后按设置间隔（默认 6 小时，与 CI 周期对齐；最小 15 分钟）。
  目标：**稳态常驻内存 < 80MB，空闲 CPU ≈ 0**。

## 5. v0 与 v1 的边界

| | v0（本仓库首个版本） | v1（后续） |
|---|---|---|
| 数据 | 只读静态 latest.json（`gacha-calendar-app` CI） | 内嵌 core，各端自行抓 28 源 |
| 来源切换 | 只支持换 feedUrl | 支持按游戏选来源 |
| 自定义条目 | 不支持 | 支持（core 的 `customEntries`） |
| 解析器自检 | 只检查 feed 可达性 / 新鲜度 / 失败条目 | 逐源 `selfCheck()` |
| 包体 | 纯 C#，无 JS 引擎 | 视引擎选择 +30–100MB |

v1 不改数据形状（仍是 core 的 Result JSON），只换来源，所以 Core 的模型与视图模型可以直接复用。
