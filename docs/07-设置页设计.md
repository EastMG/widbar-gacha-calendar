# 07 · 设置页设计：宿主 chrome + WinUI SettingsCard

> 结论先说：**WidBar 没有"设置页模板"可继承，只有一个窗口 chrome 契约。**
> 所以"基于 WidBar 原本的模板"正确做法不是回退到旧表单，而是：
> **chrome / 尺寸 / 间距完全交给宿主，内容用 WinUI 3 SettingsCard 规范排版。**

## 1. 宿主到底给了什么（来自 SDK 反编译，`WidBar.SDK.Hosting.SettingsHostWindow`）

| 项 | 值 | 谁提供 |
|---|---|---|
| 窗口首选尺寸 | **1120 × 820 dip**（超出工作区 92% 时收缩） | 宿主 |
| 标题栏 | 48 dip，`ExtendsContentIntoTitleBar`，图标 + 插件名 | 宿主 |
| 内容滚动层 | `ScrollViewer`，**Padding = 24,16,24,8** | 宿主 |
| 底部按钮 | 右对齐「保存 / 取消」，`Margin = 24,12,24,20`，`MinWidth = 120` | 宿主 |
| 背景 | Mica（不支持时 Acrylic / 纯色 #F3F3F3 / #202020） | 宿主 |
| 主题 | **跟随系统**（`SystemUsesLightTheme` 注册表 / `UISettings`），不是 WidBar 的 ThemeMode | 宿主 |
| 插件内容 | `CreateSettingsContent()` 返回的 `UIElement`，**直接塞进 ScrollViewer** | 插件 |

冻结自 SDK 源码 `SettingsHostWindow.cs`：`PreferredWidthDip=1120`、`PreferredHeightDip=820`、
`Padding(24,16,24,8)`、`val6.Margin(24,12,24,20)`。

**由此得到两条硬约束：**

1. 插件内容**不要**再套第二层 `ScrollViewer`（会双滚动 / 吃掉滚轮）；
2. 插件内容**不要**自带大外边距与窄 `MaxWidth`（宿主已给 24 左右边距；内容区约 **1072dip** 宽）。

> 旧版设置页（v0.1.0–0.1.16）恰好两条都踩了：`ScrollViewer` + `Padding 4,2,16,16` + `MaxWidth 720`。
> 在 1120dip 的宿主窗口里，它只会缩在左上角一条窄栏里 —— 所以"看起来是 WinUI 风格"不等于"符合宿主契约"。
> 旧版留档：`docs/design/settings-form-0.1.0.xaml`（仅参考，不参与编译）。

## 2. 采用方案：宿主 chrome + SettingsCard（手写）

```
SettingsHostWindow（宿主）
├─ 48dip 标题栏（宿主）
├─ ScrollViewer(Padding 24,16,24,8)（宿主）
│  └─ SettingsView（插件，本方案）
│     ├─ 分区：16 SemiBold 标题 + 12 secondary 说明
│     └─ 卡片栈（Spacing 4）
│        └─ Border: CardBackgroundFillColorDefaultBrush / CardStrokeColorDefaultBrush
│                  BorderThickness 1 / CornerRadius 8 / Padding 16,14
│           └─ Grid: * 标题(14)+说明(12)  /  Auto 控件   MinHeight 56  ColumnSpacing 16
└─ 底部 保存/取消（宿主）
```

设计令牌（全部 `ThemeResource`，不写死颜色）：

| 项 | 值 | 依据 |
|---|---|---|
| 分区标题 | 16 / SemiBold / TextFillColorPrimary | WinUI 3 type ramp |
| 分区说明 | 12 / TextFillColorSecondary / Wrap | 同上 |
| 卡片行标题 | 14 / TextFillColorPrimary / Wrap | SettingsCard 规格 |
| 卡片行说明 | 12 / TextFillColorSecondary / Wrap | 同上 |
| 卡片 | 圆角 8、1px CardStroke、Padding 16,14 | Fluent 卡片 |
| 行高 | MinHeight **56**（原 40 偏紧） | Win11 设置节奏 |
| 分区间距 | 24；卡间距 4 | 8px 网格 |
| 控件 | ToggleSwitch（无 On/Off 文案）、NumberBox、ComboBox、SubtleButton 32×32 | Win11 设置同款 |

## 3. 为什么不直接回退旧表单

| 维度 | 旧表单（v0.1.0） | 卡片方案（本方案） |
|---|---|---|
| 与宿主布局 | ❌ 双 ScrollViewer、窄栏 | ✅ 去掉内层滚动、铺满内容区 |
| 扫读 | 纯标签堆叠，28 款条目混在表单里 | ✅ 分区 + 卡片分组，控件右对齐 |
| 与 Windows 设置一致 | 泛化 WinUI 控件，缺少 SettingsCard 节奏 | ✅ 同款卡片 / 行高 / Secondary 说明 |
| 扩展 | 加一组设置就多一段 StackPanel | ✅ 加卡片即可；未来可换 SettingsExpander |
| 维护成本 | 手工布局，宿主尺寸变化时易错 | ✅ 只依赖宿主 chrome + 主题令牌 |

## 4. 备选方案（记录备查）

- **社区工具包 `CommunityToolkit.WinUI.Controls.SettingsControls`**：提供官方 `SettingsCard` / `SettingsExpander`，
  键盘 / 焦点 / RTL 由控件处理，最"原生"。代价：多一个 NuGet 依赖（约 +数十 KB 包体）与版本耦合；
  v0 内容简单，手写卡片已足够。**若以后要折叠式高级设置（SettingsExpander），再切这个包。**
- **纯表单（旧版）**：不做。

## 5. 落地与验收

- 文件：`src/GachaWidget/Views/SettingsView.xaml`（仅 XAML，`.xaml.cs` 未改）；
- harness 已按宿主 chrome 1:1 模拟（1120×820、48 标题栏、24/16/24/8 滚动区、底部保存/取消）：
  ```powershell
  GachaWidget.exe --ui-preview=settings --theme=light
  ```
- 截图：`docs/images/design-settings.png` / `design-settings-light.png`；
- 改动设置项时的检查清单：
  1. 不新增外层 `ScrollViewer` / 大 `Padding` / 窄 `MaxWidth`；
  2. 新行用 56 行高 + 卡片；
  3. 文案 ≤ 2 行，控件在右列；
  4. 只用 `ThemeResource`，深浅色各截一张。
